# Инфраструктура для UI автотестов (VDS / CI)

Этот репозиторий содержит готовую **Infrastructure as Code** для развертывания безопасного, отказоустойчивого и автоматизированного окружения под браузерные UI тесты.

Основным движком выступает официальный **Selenium Grid 4** в режиме *Dynamic Grid*. Это значит, что Docker-контейнеры с браузерами (Chrome, Firefox, Edge) создаются мгновенно в фоне *только в момент запуска тестов* и автоматически удаляются по их завершению. Это позволяет кратно сэкономить ресурсы VDS по сравнению со статичными фермами, избежав утечек памяти браузеров.

---

## 🔒 Безопасность из коробки
Ни один приватный стенд не должен торчать наружу открытым Selenium-портом 4444 (его быстро находят ботнеты). В данной сборке:
- **Traefik Reverse Proxy:** маршрутизирует трафик в изолированную Docker-сеть (никакие контейнеры не светят портами наружу, кроме 80 и 443).
- **Let's Encrypt:** Traefik автоматически выпускает и продлевает валидные HTTPS (SSL) сертификаты для вашего домена (тесты гоняются по защищенному шифрованному каналу).
- **Basic Auth:** Установлен парольный доступ к хабу. 
- **Bash Автоматизация:** В проекте есть скрипты первичной настройки сервера (отключают пользователя root, доступ по паролю, ставят файрволы). Не нужно быть DevOps'ом, чтобы безопасно настроить VDS.

## 🚀 Пошаговая инструкция по внедрению

Захотели развернуть ферму на новом проекте? Следуйте этим шагам:

### Шаг 1. Подготовка сервера и домена
1. Арендуйте Ubuntu VDS-сервер (рекомендуется 22.04 LTS или 24.04 LTS). Минимальные требования сильно зависят от параллельности тестов (обычно 4 ядра / 8 ГБ RAM). При покупке **обязательно** укажите ваш открытый SSH-ключ.
2. В управлении доменами (Selectel, Cloudflare, Reg.ru и т.д.) создайте A-запись, направляющую логичное доменное имя (например, `selenium.myproject.com`) на IP-адрес вашего нового VDS-сервера.

### Шаг 2. Как задеплоить руками? (Ручной подход)
Если вы не хотите использовать GitHub Actions.
1. Подключитесь к серверу: `ssh root@IP_ВАШЕГО_СЕРВЕРА`
2. Скопируйте папку `selenium_grid_4` на сервер.
3. Внутри этой папки скопируйте шаблон переменных окружения: 
   ```bash
   cp .env.example .env
   ```
4. Отредактируйте `.env`: впишите туда ваш e-mail (для SSL), ваш домен и хеш для Basic-авторизации (в `.env.example` написано, как его сгенерировать).
5. Находясь в этой папке, запустите инфраструктуру:
   ```bash
   sudo docker compose up -d
   ```
*(Один раз в минуту Traefik будет стучаться в Let's Encrypt и при первом деплое это займет около минуты, пока у вас не появится замочек в браузере).*

### Шаг 3. Как задеплоить автоматом? (CI/CD через GitHub Actions)
В проекте настроен экшен `.github/workflows/deploy-grid.yml`, который развернет всё сам, настроив при этом железную безопасность самого Ubuntu сервера (Fail2ban, ufw файрвол, запрет root-доступа). 

1. Сгенерируйте пароль для доступа к Selenium (`SELENIUM_PASSWORD`) — это просто текст, например `SuperSecret2027!`.
2. В настройках этого GitHub-репозитория (`Settings` -> `Secrets` -> `Actions`) добавьте два секрета:
   - `SSH_PRIVATE_KEY` (Обязательно: приватная часть того SSH-ключа, которым вы инициализировали сервер).
   - `SELENIUM_PASSWORD` 
3. Перейдите во вкладку **Actions**, выберите слева "Deploy Selenium Grid to Clean VDS" и нажмите **Run workflow**. 
4. Заполните данные (IP сервера, Почту, Домен, Логин). Action всё сделает сам!

## ☕ Использование в тестах (Пример для Java)

Хранить пароль открытым текстом прямо в коде тестов — **небезопасно** (он попадет в Git и будет доступен всем разработчикам). Правильный подход — передавать логин, пароль и хост через переменные окружения ОС (Environment Variables) или через System Properties, которые подставятся на этапе запуска сборки (в CI/CD).

Пример защищенной настройки `RemoteWebDriver` в Java:

```java
import org.openqa.selenium.chrome.ChromeOptions;
import org.openqa.selenium.remote.RemoteWebDriver;
import java.net.URL;

public class BrowserFactory {
    public static RemoteWebDriver createDriver() throws Exception {
        ChromeOptions options = new ChromeOptions();
        
        // 1. Получаем секреты из переменных окружения (настраиваются в GitHub Actions / Jenkins / GitLab CI)
        // Предварительно задайте дефолтные значения для локальной отладки (если нужно)
        String seleniumUser = System.getenv("SELENIUM_USER"); 
        String seleniumPass = System.getenv("SELENIUM_PASS");
        String seleniumHost = System.getenv("SELENIUM_HOST"); // например: selenium.yourdomain.com
        
        if (seleniumUser == null || seleniumPass == null || seleniumHost == null) {
            throw new IllegalArgumentException("Не заданы креды для Selenium Grid! Проверьте переменные окружения.");
        }
        
        // 2. Формируем безопасный URL с Basic Auth
        String gridUrl = String.format("https://%s:%s@%s/wd/hub", seleniumUser, seleniumPass, seleniumHost);
        
        // 3. Запускаем сессию
        return new RemoteWebDriver(new URL(gridUrl), options);
    }
}
```

> **Примечание:** Устаревшая реализация на базе Aerokube Selenoid для исторических целей перенесена в директорию `legacy_selenoid`. Читайте README внутри нее, если нужно поддержать легаси-проект.
