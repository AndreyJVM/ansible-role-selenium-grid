# Инфраструктура для автотестов на VDS (Selenium & Selenoid)

Этот репозиторий содержит конфигурацию для развертывания окружения параллельного выполнения браузерных автотестов на VDS (например, в Selectel) с использованием Docker. 

В проекте представлены два подхода: **современный** (через официальный Selenium Grid 4) и **классический/устаревший** (через Aerokube Selenoid).

---

## Современный подход: Selenium Grid 4 (Dynamic Grid)

**Статус:** Рекомендуемый вариант.
**Директория:** [`/selenium_grid_4`](./selenium_grid_4/)

Современная официальная реализация Selenium Grid существенно обновилась и теперь умеет динамически поднимать и "убивать" Docker-контейнеры "на лету" (Dynamic Grid) — функционал, ради которого раньше все использовали Selenoid. 

**Преимущества этого подхода:**
- **Активная поддержка:** Проект постоянно обновляется, поддерживаются новые версии браузеров (в отличие от Selenoid, разработка которого свёрнута).
- **Экономия ресурсов VDS:** Контейнеры с браузерами запускаются только тогда, когда приходит запрос от теста, и сразу же уничтожаются по завершению.
- **Встроенная безопасность:** В обвязке настроен **Traefik**, который скрывает внутренние порты Docker-сети, автоматически генерирует и продлевает SSL-сертификаты (HTTPS) от Let's Encrypt и защищает доступ с помощью Basic Auth пароля (ваших мощностей не коснутся ботнеты).

**Как запустить:**
1. Перейдите в папку `selenium_grid_4`.
2. Ознакомьтесь с инструкциями по настройке сертификатов и паролей в файле `docker-compose.yml`.
3. Запустите стек: `docker-compose up -d`.

##  Устаревший подход: Aerokube Selenoid + GGR

**Статус:** Устаревший (Архивирован разработчиками в конце 2024 года).

**Директория:** [`/legacy_selenoid`](./legacy_selenoid/)

**Схема архитектуры:** 

![Selenoid-schema.png](img/Selenoid-schema.png)


Классический подход с использованием Aerokube Selenoid балансировщика GGR, Nginx для проксирования, и интерфейсов GGR-UI / Selenoid-UI. Идеален для распределения нагрузки между множеством физических серверов, но избыточен для одного VDS и больше официально не развивается (Aerokube сфокусировались на Kubernetes-решении Moon).

Код сохранён в целях совместимости со старыми серверами и для истории.

**Структура старого подхода:**
1. `1-selenoid` — настройка нод Selenoid.
2. `2-ggr` — балансировщик (Grid Router).
3. `3-ggr-ui` — UI интерфейс для балансировщика.
4. `4-selenoid-ui` — UI интерфейс для самой ноды.
5. `5-nginx-proxy` — прокси сервер для привязки.
- `docker-compose.yml` — единый файл запуска старой инфраструктуры.
- `setup.sh` — стартовый bash скрипт для инициализации.
